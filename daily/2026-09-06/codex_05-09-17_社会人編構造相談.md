# 社会人編から始める構成の相談回答

Gitの競合は解消済みです。ローカル側の旧「相談1」ではなく、リモート側で書き始められていたテックリード配属シーンを本文に採用し、マージコミット `8a5c656` を作成しました。本文の表現には手を加えていません。

## 結論

社会人の樹がテックリードとして秀斗の上司になる場面から本編を始める案は、かなり実現性があります。むしろ、過去を順番にすべて描くより、現在の衝突を物語の背骨にして、必要になった過去だけを回想で開く方が、この作品の「理解しようとするほど相手を傷つける」という中心葛藤に早く入れます。

ただし、次の区別が重要です。

- **配属・再会**：オープニングの異常事態／フック
- **樹が秀斗への接し方を選ぶ瞬間**：契機事件
- **その選択が秀斗を実際に傷つけ始める**：進行する複雑化
- **秀斗の崩壊・自殺未遂**：危機からクライマックス

配属だけでは樹の人生に変化が起きず、単なる「出来事」で終わる恐れがあります。Story Compilerの契機事件は、均衡を壊し、主人公に欲望を生み、反応ではなく選択と行為を起こさせる必要があります。

## 推奨する物語エンジン

最も強いのは、次の因果です。

```text
樹が秀斗のテックリードになる
→ 秀斗が一瞬だけ露骨な敵意を見せる
→ 樹には理由が分からない
→ 秀斗から「昔の仕返しか」または、それに近い疑いを向けられる
→ 樹は、自分が私情で評価していると思われることを恐れる
→ 「誰より公平に、曖昧さなく、丁寧に指導する」と選ぶ
→ 指摘・評価基準・長文フィードバックを過剰に厳密化する
→ その善意が、秀斗には過去の教育虐待の再演として届く
→ 秀斗が壊れる
```

この場合、契機事件の本体は「秀斗に恨まれたこと」ではありません。**恨みを受けた樹が、公平であろうとして危険な方法を選ぶこと**です。

この選択なら、樹の善の中心も守れます。樹は秀斗を陥れたいのではなく、過去の関係を評価へ持ち込むのは不正だと本気で考えている。その誠実さが、他者の感情を受け止めないまま運用されることで暴力になります。

## 「出会いだけ」か「すぐパワハラ」か

どちらか一方に振り切らず、**初回は小さな加害が本人に見えないところまで**進めるのがよいです。

### 出会いだけで切る場合

読者の問いは「なぜ秀斗は樹を睨んだのか」になります。フックとしては成立しますが、樹がまだ何も選んでいないため、場面の価値変化が弱いです。「不穏な再会」で止まり、物語のエンジンは次の場面まで始まりません。

### 初回から明白なパワハラをする場合

展開は速い一方、樹が最初から明確な加害者に見えます。善意と暴力の境界を読者が考える余地が減り、秀斗の崩壊までのエスカレーションも平坦になります。

### 推奨案

配属説明の直後に、樹が「安心させるための言葉」を選び、それが脅しに聞こえるところまで書きます。

たとえば樹は、秀斗を公平に扱う意思を伝えるために、次のような趣旨を口にする。

> 昔の関係が、君の評価に影響することはない。成果物だけで判断する。

樹にとっては保証です。しかし秀斗には、「逃げ場なく成果を査定する」「昔のことは覚えている」という宣告にも聞こえます。

秀斗は笑って「助かります」と返す。樹は言葉どおり受け取り、説明は成功したと思う。だが、机の下で秀斗の指だけが止まっている。この**期待と結果のずれ**が、最初の小さなパワハラであり、後の破局の種になります。

## 冒頭で見せる「完成された自我」

成人の樹を「昔より成長した」「社会適応できる」と説明する必要はありません。次のような、身につけた手続きを見せれば十分です。

- 相手の目ではなく眉間を見ることで、アイコンタクトを再現する。
- 挨拶の秒数や笑顔を閉じるタイミングを覚えている。
- 会議前に、雑談候補をメモしている。
- 相手が話し終わってから一拍置くことを意識している。
- 「まず相手を肯定する」という会話手順を実行するが、肯定部分が定型的すぎる。
- 恐怖や困惑を、感情ではなく「追加情報が不足している状態」と処理する。

ここで重要なのは、樹を「人間の真似をするロボット」として突き放さないことです。彼は仲良くしたいし、公平でありたいし、相手を傷つけたくない。そのために必死で手続きを覚えた。その努力が見えると、不自然な振る舞いが共感と謎の両方になります。

読者に作る中心的な問いは、一つに絞った方が強いです。

> なぜ、この有能で善良そうな男は、秀斗をこれほど怯えさせているのか。

「なぜ秀斗は恨んでいるのか」だけだと、答えが過去のいじめや嫉妬に限定されます。上の問いなら、秀斗の過去と樹の現在の加害性の両方が答えになります。

## 現在の配属シーンのStory Compiler診断

### `pass`：強いところ

- 睨みから始まり、すぐ「なぜ？」が生まれている。
- 組織図によって、樹が秀斗の上位に置かれた事実を短く提示できている。
- 樹には敵意が理解できず、秀斗には樹の地位が脅威になるという極性がある。
- 社会人の現在から過去を開く構成に向いたフックになっている。

### `warning`：弱いところ

1. **樹がまだ選択していない**  
   現状は「睨まれた、分からない、怖い」で終わっています。ニュースへの反応であり、場面の結果が次の出来事を生んでいません。

2. **秀斗の内面を樹が知りすぎている**  
   POV設定は三人称一視点・樹・`subject_native`です。「周りに悟られないようにした」は秀斗の意図を断定しています。樹が観察できる動作へ戻した方が視点が安定します。

3. **樹の特異性を説明している**  
   「人間の表情に疎い樹ですらわかった」より、樹が唇の角度、返事までの時間、視線の固定などを観測し、いつもの秀斗との差分として異常判定する方が、成人した樹の認知を見せられます。

4. **比喩が先に答えを出している**  
   オオスズメバチ、作り笑顔の仮面、大きな蜂への硬直が短い範囲に重なっています。敵意と恐怖を強く説明するため、読者が挙動を読み取る余地が狭くなっています。初稿では残して構いませんが、後で一つに絞れます。

5. **名前が設定と不一致**  
   現稿では「修斗」、設定資料では「秀斗」です。初稿の勢いを止める問題ではありませんが、次の整理時に統一が必要です。

## 回想の使い方

社会人編を現在軸にするなら、回想は「昔はこうでした」という説明ではなく、現在の行動の意味を変える地点だけに置きます。

悪い接続は次です。

```text
秀斗を見た
→ 昔を思い出した
→ 幼少期を順番に説明する
```

推奨する接続は次です。

```text
現在の秀斗が、樹の指導に「前にもそうやったよな」と漏らす
→ 樹には何を指すのか分からない
→ 過去の同型場面を見せる
→ 読者には意味が分かるが、現在の樹は誤った解釈をする
→ その誤解に基づいて、樹が指導をさらに厳密化する
```

この形なら回想が現在の行動を妨害・方向転換し、Story Compilerのフラッシュバック条件を満たします。

## 小学生編と中学生編の統合

**中学生編へ統合する案はありです。**　現在のプロローグの日記が2011年5月13日で、1997年生まれの樹なら中学生時代に当たるため、むしろ冒頭との整合もよくなります。

統合する場合は、出来事ではなく因果の順序を守ってください。

```text
父から、受容と「仮説を立てる」方法を受け取る
→ 秀斗との翻訳事故が起きる
→ 樹は対人関係まで分析対象にする
→ あんずと出会い、分析せずにいられる沈黙を経験する
→ あんずの相談を正しい提案で処理する
→ あんずの死により「曖昧な言葉は人を殺す」という誤信が固まる
```

この順序さえ残れば、小学校という年代そのものは不可欠ではありません。

ただし、父の死、秀斗との亀裂、あんずとの出会いと死を同じ中学時代に集めるため、「不幸が集中しすぎる」危険があります。中学1年・2年・3年の時間差を置き、全期間を連続して描かず、現在の衝突へ必要な四つ前後の場面だけを選ぶのがよいです。

### 残すべき過去の最小単位

1. **テスト返却日**  
   樹は不完全な点数でも父に受け入れられ、秀斗は満点でも条件付きでしか愛されない。秀斗の羨望の根になります。

2. **樹と秀斗の最初の翻訳事故**  
   樹の正しい説明が、秀斗には見下しとして届く。現在のコードレビューと同型にします。

3. **父の「辛いやろ」または仮説の場面**  
   樹が本来受け取った「受け止める→翻訳する→提案する」の原型を置きます。

4. **あんずへの応答と死**  
   樹が「受け止める」を落とし、正しい提案だけを渡すようになる決定的原因です。

この四場面以外は、初稿を書きながら本当に必要になった時に追加できます。

## ここから先に書く順番

最終掲載順ではなく、因果を発見しやすい執筆順です。

### 1. 配属直後の短い1on1

樹の目的は秀斗を安心させること。樹は公平性を言語化する。秀斗は表面上同意するが、関係は安心から警戒へ悪化する。

```text
before：再会の敵意は理由不明
action：樹が公平性を保証する
expectation：秀斗が安心する
result：秀斗の警戒が深まる
gap：正確に説明したのに、なぜ悪化したのか
```

### 2. 最初のコードレビュー

樹の指摘は技術的に完全に正しいものにします。秀斗は修正するが、普段ならしない単純なミスを増やす。樹は「説明量が足りない」と誤診します。

### 3. 中学時代の最初の翻訳事故

現在のレビューと同じ言葉、同じ身振り、同じ沈黙のどれかをトリガーにします。回想後、読者には反復が見える一方、樹は「昔も説明不足だった」と逆方向へ結論づけます。

### 4. 現在で樹が指導を制度化する

口頭で伝わらなかったため、評価基準、チェックリスト、長文Slack、定例1on1を導入する。ここが不可逆的コミットメントです。以後、樹は「たまたま言い方を間違えた」では済まなくなります。

### 5. 父の場面

現在の樹が「まず問題を定義しよう」と言った地点で、父が樹を先に受け止めてから仮説を教えた過去を置く。読者は、樹が父の教えの最初の一段を失っていると理解します。

この五つを書けば、全体プロットを確定しなくても、現在の加害と過去の由来を往復する物語のエンジンが見えるはずです。

## 現時点のコンパイル判定

| 項目 | 判定 | 理由 |
|---|---|---|
| 社会人編から開始 | `pass` | 中心葛藤と謎へ早く入れる |
| 配属を契機事件にする | `warning` | 配属だけでは欲望・選択・不可逆な結果がない |
| 配属場面で軽微な加害まで描く | `pass` | 期待と結果のギャップを作れる |
| 冒頭から明白なパワハラ | `warning` | 善意との両義性とエスカレーションを失う |
| 回想で幼少期を開示 | `conditional pass` | 現在の意味や行動を変える回想に限る |
| 小中学生編を中学生へ統合 | `pass` | 年代より因果順序を維持できれば成立する |
| 現稿のPOV | `warning` | 秀斗の意図を樹が断定する箇所がある |

したがって、次に書くべきなのは過去編全体ではなく、**配属直後の1on1で、樹が善意から最初の間違った選択をする場面**です。その場面まで書けば、配属が単なる再会ではなく、物語全体を動かす契機へ変わります。
