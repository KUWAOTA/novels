# constrain/main/ フォルダ構造設計（McKee準拠）

## 構造の根拠

Robert McKee "Story" の**5階層構造**に基づいてフォルダを分割した。

```
Story > Act（幕）> Sequence（シーケンス）> Scene（シーン）> Beat（ビート）
```

- **フォルダ = Act / Sequence**（構造単位）
- **ファイル = Scene**（最小の価値変化単位。各.mdにbeat候補も記載）
- 各Scene.mdは `story-compiler/templates/scene.yaml` の構造に準拠（value_change, continuity, beats）

## 各Scene.mdの構造

McKee + story-compiler の `scene.yaml` テンプレートに準拠：

```yaml
type: Scene
id: ACT2-SEQ2-S3           # 階層的ID
summary: ...                 # 1行要約
axes: [...]                  # 動く価値軸
value_change:                # 価値変化（必須）
  axis: ...
  from: ...
  to: ...
  cause: ...
continuity:                  # 連続性
  time: ...
  space: ...
  pov: ...
```

＋ narrator（視点キャラ・自称）、ビート候補、象徴的台詞、演出ノート、【穴】を Markdown で記載。

各ファイルの末尾に `## 本文` セクションがあり、そこに執筆する。

## 書き始めるシーン

**ACT2/SEQ2_引き金/S3_あんずとのデート.md** を最初に書く。

理由：
- ユーザーの直感（B子とのデートが書きやすい）
- 黒田レビュー「イメージがついているところから書く」
- 物語の最重要転換点（「善意が人を殺す」三重構造の①）に直結

このシーンのファイルは準備済み。`## 本文` の `<!-- ★ ここから書き始める ★ -->` マーカーあり。
